## 1. Summary

Companies that roll Gita out today send developers a list of manual steps
(install tools, add profiles, sign in, clone a handbook repo, import company
files). `gita onboard <file>` does all of it from one **onboarding file** the
company writes once, and is safe to run again. It also removes old GitHub
sign-ins that make git or gh use the wrong account, and offers to delete old
backups of earlier runs. User docs: [docs/onboarding.md](../../docs/onboarding.md).

## 2. Decisions

| # | Decision |
|---|---|
| D1 | Generic: nothing company-specific in Gita; the company's steps live in its onboarding file. |
| D2 | Separate file format, not an extension of the company file (old Gita ignores unknown company-file keys and rewrites the file without them). |
| D3 | Fixed step types only (`signIn`, `repo`, `companyFile`, `repoScript`, `claudeCode`, `doctor`): the file can't run arbitrary commands. |
| D4 | Gita reads the file from a local path only; it never downloads it. |
| D5 | Tools: git, gh, Claude Code (and `secret-tool` on Linux) are checked and installed or repaired with winget / Homebrew and Xcode tools / apt, dnf, pacman (sudo command shown first, sudo asks) / Claude Code's official installer. |
| D6 | Clean-up of old GitHub sign-ins lists everything first, asks (no terminal: keeps), backs up `~/.gitconfig`, and never touches Gita's own sign-ins, other sites or SSH keys. |
| D7 | Old backups (`~/.gitconfig.backup-<date>`, `<repo>.backup-<date>`) older than 30 days are offered for deletion; the newest of each is kept. |
| D8 | Sign-in asks for `read:org` too, so `gita gh` can run organization and team commands. Existing sign-ins keep working. |
| D9 | Releases publish `SHA256SUMS`, so installers that pin a version can check new releases. |

## 4. Security checklist

- [x] Onboarding file: local only, 64 KB cap, strict schema (unknown keys rejected), length limits, control and bidi characters rejected, paths confined to the home folder / the cloned repo.
- [x] No free-form commands; repo scripts must be inside a repo cloned by the same file, are shown first and get no terminal input.
- [x] Programs start directly, never through `cmd.exe`, except `.cmd`/`.bat` shims with plain arguments.
- [x] Tokens never printed or logged; tokens in old git setting names shown as `//***@`; git's credential answers discarded.
- [x] `.gitconfig` backups owner-only; old ones offered for deletion because they can hold removed tokens.
- [x] Package installs use fixed package names; `sudo` only for the package manager command.
- [x] Timeouts on every external command.
- [x] Tests never use the real home or password store.
