## 1. Summary

People keep being told to "sign in to Gita again" when they push. The cause
found on the admin's computer: GitHub cancelled the token saved for the
"ThoughtBox" profile (it answers `401 Bad credentials`). Gita still showed the
profile as signed in and the Doctor said everything was fine. So each push
failed with an unclear message, and the person had no way to see why.

GitHub keeps at most 10 tokens per account for one OAuth app. Each new sign-in
makes a new token, and the oldest is cancelled. Signing in again "just in case"
can therefore cancel a token another computer still uses.

This change makes Gita **check that each saved sign-in still works**, show a
dead one clearly, and avoid sign-ins that aren't needed.

## 2. Understanding and assumptions

- **Goal:** a dead sign-in is found and named before the person is stuck, and
  the fix is one step ("Sign in again").
- **Users:** people who are not git experts, the Gita app, the `gita` command,
  and AI tools through `gita mcp`.
- **Assumption A1:** `GET https://api.github.com/user` with the token is the
  check. `200` means it works (and gives the account name). `401` means GitHub
  rejected it. Anything else (no internet, timeout, GitHub down, rate limit)
  means "don't know", and Gita says nothing rather than raise a false alarm.
- **Assumption A2:** the next version is `1.1.0` (the app is at `1.0.0`; this
  adds features). `/promote` decides the real number.
- **Assumption A3:** the check may run each time the Doctor runs (app start,
  `gita doctor`, `gita_doctor`). It costs one small request per signed-in
  profile, at most 10 seconds each, and results are kept for 5 minutes.

## 3. Scope

In scope:

1. **Sign-in check** (`SignInChecker`) in the core, with a GitHub adapter.
2. **Doctor**: two new findings, "sign-in stopped working" (blocking) and
   "signed in as a different GitHub account" (warning). Both offer
   "Sign in with GitHub". Shown in the app, `gita doctor` and `gita_doctor`.
3. **Push failure message**: when git reports that GitHub rejected the sign-in,
   the `gita` credential helper checks the token and says plainly which case it
   is and the one step to fix it.
4. **No needless sign-ins**: `gita sign-in` and `gita_sign_in` do nothing when
   the saved sign-in already works for the right account, unless `--force`
   (`force: true`).
5. **App profile dialog** shows "This sign-in stopped working" with a
   "Sign in again" button instead of "Signed in as @…".

Out of scope:

- SSH keys per profile as a replacement for HTTPS (option D; not approved).
- Remembering failures on disk, or refreshing tokens automatically (GitHub
  OAuth tokens can't be refreshed; a new sign-in is the only fix).
- Changing how tokens are stored.

## 5. Design decisions

- **D1 — Port and adapter.** `SignInChecker` is an interface in
  `lib/core/services/sign_in_checker.dart`; `GitHubSignInChecker` uses the
  existing `GitHubHttp`, so tests fake it. It returns `working(login)`,
  `rejected` or `unknown`. The token is sent only to `api.github.com` over TLS
  and is never printed or logged.
- **D2 — Silence on doubt.** Only a `401` counts as rejected. A wrong answer
  would send people to sign in again for nothing, which is the problem C is
  meant to avoid.
- **D3 — Short timeout and cache.** 10 seconds per check; results cached in
  memory for 5 minutes per token, so the app's Doctor reruns don't repeat the
  requests. A new sign-in has a new token, so the cache never hides it.
- **D4 — Tests stay offline.** `GitaCli` uses the real checker only when it
  also uses the real token store. A caller that passes its own store (every
  test) passes its own checker or gets none.
- **D5 — Skip, don't block.** `gita sign-in` skips only the device flow when
  the sign-in works for the expected account. `--with-token` always saves what
  it is given. `--force` signs in anyway (to switch accounts).
- **D6 — Leave the token in place on erase.** As before, deleting it would
  hide what happened; the Doctor and the dialog now show it instead.

## 6. Security checklist

- [x] Token never printed, logged or put in JSON output or error messages.
- [x] Only sent to `https://api.github.com/user`, TLS with normal certificate
      checks, 10 s timeout.
- [x] Account names from GitHub shown as text only (no HTML).
- [x] No new dependencies.
- [x] No change to git's credential settings.

## 7. Test approach

- Unit: checker (200 / 401 / 500 / timeout / bad JSON / cache), Doctor (rejected,
  wrong account, unknown, no checker), fixes mapping, CLI `credential erase`
  (three cases), `sign-in` skip and `--force`, MCP `force` argument.
- `flutter analyze`, full `flutter test`, `dart build cli`.
- Live, read-only: `gita doctor` on the admin's real setup should now report
  the ThoughtBox sign-in as stopped working, without printing the token.
