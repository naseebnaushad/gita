## 1. Summary
There is no way to remove a project from the Gita Dashboard. This CR adds a **Remove** action to each project row, and the same action in the terminal as `gita untrack <path>`. Remove takes Gita's safety check out of the project and drops it from the list. The folder is never touched.

The onboard repair was split out of this CR and ships first as CR-1.1.2-01.

## 2. Answers to the clarifying questions
| Topic | Answer |
|---|---|
| Goal | People can tidy their Dashboard. |
| Users | Gita desktop app users on all platforms, and terminal users. |
| In scope | A per-row Remove action with a confirmation. It also removes the safety check (restoring the project's own hooks). Adds `gita untrack <path>`. |
| Out of scope | Deleting folders. Bulk remove. |
| Edge cases | **Folder already gone:** remove the entry and skip the safety check. **Project with its own hooks:** they are put back. **Rerunning setup:** may add the project again if a scan finds it (documented). |
| Constraints | One core use case serves the UI and the CLI. No new dependencies. |
| Definition of done | Widget and unit tests pass, docs are updated, a change note is written, and a manual check is done on macOS. |

## 4. Decisions (proposed)
| # | Decision | Reason |
|---|---|---|
| D1 | Remove = uninstall the safety check + delete the entry. It never touches the folder. | That is the expected meaning of "remove from Gita". |
| D2 | A confirmation dialog, no Undo. | Simple, and prevents mis-clicks. |
| D3 | One core use case for the Dashboard and `gita untrack`. | Shared core, thin front-ends. |
